# Noroshi Donate — Website

Сайт доната для Minecraft-сервера **Noroshi**: витрина, каталог, оплата, визуальный редактор, панель владельца и защищённый API для плагина
[noroshi-donate-plugin](../noroshi-donate-plugin). Репозиторий независим от плагина — связь только через [документированный API](docs/API.md).

**Стек:** Node.js ≥ 22.13, **без внешних npm-зависимостей** (SQLite из самой Node, свой SMTP-клиент) — `npm install` не нужен.

## Возможности
- Главная и дополнительные страницы собираются из блоков (заставка, текст, преимущества, статус сервера, привязка аккаунта, каталог, FAQ и др.).
- Кнопка ✎ → визуальный редактор: добавление/удаление/перестановка блоков (в т.ч. перетаскиванием), правка текстов и изображений, предпросмотр, черновик и публикация, управление страницами и меню. Тексты, изображения, товары и цены меняются без правки кода.
- Привязка Minecraft-аккаунта **кодом, подтверждаемым в игре** (`/donate confirm КОД`). Ввода чужого ника недостаточно. Отвязка тоже подтверждается в игре владельцем аккаунта. Пароли Minecraft не запрашиваются.
- Каталог: карточки, страницы товаров, категории, порядок, включение/отключение, цена в UAH, команды выдачи.
- Оплата: **LiqPay** (карты, Google Pay, Apple Pay — зависит от вашего мерчанта) и **тестовая оплата**. Товар выдаётся только после подписанного уведомления провайдера; переход на страницу «успех» ничего не выдаёт.
- Валюты: учёт в UAH; покупателю — UAH/EUR/USD (если принимает провайдер). Курс НБУ или ручной, **курс фиксируется в заказе**.
- «Доходы»: за день/неделю/месяц/всё время, оплачено / комиссии / к получению / возвраты, заказы по статусам, график, история транзакций, статусы выдачи.
- Два владельца (`oartem0912@gmail.com`, `amongtem151@gmail.com`) с полными правами; вход по коду на почту; замена адреса, передача роли и платёжные настройки подтверждаются кодом на второй адрес.
- Безопасность: HMAC-подпись запросов плагина и ответов, защита от повторов (nonce + время), идемпотентность платежей и выдачи, проверка суммы/валюты, CSP, защита от CSRF (Origin/Sec-Fetch-Site), лимиты запросов, журнал, ежедневные резервные копии с проверкой.

## Быстрый старт (локально)
```bash
cp .env.example .env        # для разработки достаточно NODE_ENV=development и TEST_PAYMENTS=true
npm run dev                 # http://localhost:3000
npm test                    # автотесты (вход, привязка, оплата, подписи, идемпотентность, резервные копии)
```
В dev-режиме без SMTP коды входа печатаются в консоль. Нажмите ✎ внизу страницы → введите почту владельца → код.

## Развёртывание (VPS + Docker + HTTPS)
1. Укажите домен в `Caddyfile`, создайте `.env` по `.env.example` (`BASE_URL=https://ваш-домен`, `PLUGIN_SECRET`, SMTP, ключи LiqPay).
   Секрет: `openssl rand -hex 32`. **`.env` не коммитится** (есть в `.gitignore`).
2. `docker compose up -d --build` — сайт за Caddy с автоматическим сертификатом. Данные — в томе `donate-data`.
3. Откройте сайт → ✎ → войдите по коду на почту.
4. В кабинете LiqPay укажите *Server URL*: `https://ваш-домен/api/webhooks/liqpay` (он же показан в «Настройки → Платежи»).
5. Установите плагин и укажите в его `config.yml` адрес сайта и тот же `PLUGIN_SECRET`.

Без Docker: `NODE_ENV=production node src/server.js` за любым reverse-proxy с HTTPS (`TRUST_PROXY=true`). Для автозапуска подойдёт systemd.

### GitHub Actions и секреты
- `ci.yml` — проверка синтаксиса, тесты, сборка Docker-образа.
- `deploy.yml` — необязательный деплой по SSH (запуск вручную). Секреты `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH` хранятся в **GitHub Secrets**; файл `.env` лежит только на сервере. Ключи платёжных систем в репозиторий не попадают.

## Платежи: что нужно знать до боевого запуска
- Реализован LiqPay. Он принимает UAH, USD, EUR; доступность Google Pay/Apple Pay определяется настройками мерчанта. Вывод в гривнах на карту возможен только для зарегистрированного бизнеса (ФОП/ТОВ) по правилам LiqPay.
- **Криптоплатежи и СБП не реализованы**: в ТЗ они допустимы только после выбора и подтверждения провайдера. Каркас готов — см. комментарий в `src/payments/index.js` (интерфейс провайдера + `processPaymentEvent`). RUB в списке валют отсутствует, пока провайдер не подтвердит законную поддержку.
- Сайт **не имитирует вывод средств**: в «Доходах» показан расчёт «к получению» по заказам; реальный баланс и выплаты — в кабинете провайдера.
- Возвраты: событие `reversed` от LiqPay переводит заказ в «Возврат» и учитывается в статистике. Автоматического отзыва выданного товара нет — вы увидите это в журнале и заказе.
- До запуска реальных платежей согласуйте провайдеров, валюты, порядок возвратов и условия вывода (раздел 16 ТЗ). Сначала проверьте всё с `LIQPAY_SANDBOX=true`.

## Резервные копии и восстановление
Каждые `BACKUP_INTERVAL_HOURS` часов в `data/backups/` создаётся снимок SQLite (`VACUUM INTO`) и сразу проверяется (`integrity_check`). Хранится `BACKUP_KEEP` копий. Вручную: `npm run backup`, проверка: `npm run backup:verify`.
Восстановление: остановить сайт → заменить `data/noroshi.sqlite` (и удалить `-wal/-shm`) нужной копией → запустить. Копируйте `data/backups` и `data/uploads` за пределы сервера.

## Заметки по эксплуатации
- Состояние ограничителя запросов и nonce хранится в памяти — запускайте **один экземпляр** приложения (SQLite тоже рассчитан на один процесс).
- Онлайн игроков берётся от плагина (heartbeat каждые ~15 с); если сигнала нет 90 с, сайт показывает «Сервер недоступен».
- Загрузка изображений: PNG/JPG/GIF/WebP до 5 МБ (SVG запрещён намеренно).
